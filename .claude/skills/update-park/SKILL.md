# Обновление парка

Админки нет: всё обновление идёт через этот гайд в чате. Источник данных один: `data/models.json`. Сборки у сайта нет, правка файла видна после перезагрузки страницы.

Сайт публичный и показывается клиентам как витрина экспертизы. Поэтому точность важнее количества: непроверенное не добавляем, прикидку не выдаём за факт.

Сначала прочитай «Визуальный язык здания» в `README.md`.

## 1. Найти обновления

Если пользователь уже назвал модель, сразу переходи к шагу 2.

1. Запусти `python tools/check_updates.py`. Скрипт покажет новые репозитории провайдеров парка с даты `as_of`.
2. Поищи в сети новые закрытые модели и новых провайдеров за этот же срок.
3. Перепроверь находки по первоисточнику: страница на Hugging Face, карточка модели, блог или документация компании. Трекеры и новостные сводки часто путают названия и даты, по ним ничего не добавляем.

Покажи пользователю короткий список с разделением: подтверждено или только в сводках; новая архитектура или дообучение. **Спроси, что добавлять, и только потом меняй данные.** Если пользователь уже просил добавить конкретные модели, повторно не спрашивай.

Что обычно не становится зданием:
- квантованные и сжатые копии тех же весов (NVFP4, FP8, GGUF и подобные);
- модели не из нашей темы: робототехника, сегментация, узкие исследовательские модели.

## 2. Добавить открытую модель

Числа берём из первоисточника, а не по памяти.

1. Скачай `config.json` и `README.md` репозитория, а также метаданные: `https://huggingface.co/api/models/<org>/<repo>` (`createdAt`, `cardData.license`, `cardData.base_model`, `safetensors.total`).
2. Посчитай этажи по формулам ниже.
3. **Сверка обязательна:** сумма `count × ffn_per_expert × (experts + shared)` по всем этажам плюс пристройки должна быть близка к общему размеру модели. Обычно FFN занимает 70–95% языковой части. Большое расхождение значит, что формула или тип MLP выбраны неверно.
4. Добавь запись в `data/models.json` рядом с моделями того же провайдера. За образец возьми похожую существующую модель.

### Формулы FFN одного эксперта

`h` — `hidden_size`, `i` — `intermediate_size` или `moe_intermediate_size`.

| Тип | Формула |
|---|---|
| С гейтом (SwiGLU, SiLU, GLU; у Gemma — gated GELU) | `3 × h × i` |
| Без гейта (GELU, ReLU, relu²) | `2 × h × i` |
| Latent MoE | вместо `h` берём сжатый размер: `moe_latent_size` или `routed_expert_hidden_size` |
| Conformer | два полу-FFN считаем вместе: `2 × 2 × h × i` |
| LSTM | `4 × (вход + h) × h` |

Гибриды Mamba (Nemotron-H) разбираем послойно по `layers_block_type` или `block_configs`, подряд идущие одинаковые слои склеиваем в один пролёт. У слоёв без FFN в данных стоит `kind: "dense"` и `mixer`:
- Mamba, `mixer: "mamba"`: `h × (2d + 2 × n_groups × ssm_state_size + mamba_num_heads) + d × h`, где `d = mamba_num_heads × mamba_head_dim`;
- внимание, `mixer: "attention"`: `2 × h × heads × head_dim + 2 × h × kv_heads × head_dim`.

Слой ViT для пристройки: `n × (4h² + 2 × h × i)`, где `i` по умолчанию `4h`. Если карточка называет размер энкодера, берём его.

### Поля записи

Каждое значение: `{ value, status, source, note }`. У `status: "estimate"` добавляем `confidence`: `high`, `medium` или `low`.

| Поле | Что значит |
|---|---|
| `id`, `name`, `provider` | `provider` точно как в списке `providers` |
| `kind` | `llm`, `speech`, `image`, `video`, `forecast`, `utility`: задаёт форму основания |
| `open_weights`, `license` | лицензия из метаданных |
| `released` | дата публикации весов на Hugging Face, для закрытых — дата анонса |
| `total_params`, `active_params` | сначала число из карточки; в заметке указываем, если safetensors расходится |
| `layers` | этажи снизу вверх: `{ count, kind: "dense" или "moe", ffn_per_expert, experts, active, shared, part, label, mixer, loop }` |
| `context` | `null`, если неприменимо, причину пишем в `note` |
| `input`, `output` | `text`, `image`, `audio`, `video`, `file`, `series`, `vector`, `score` |
| `annexes` | части вне слоёв: `{ kind, name, value, status, source, note }` |
| `retrain` | см. раздел «Дообучение» |
| `realtime` | `true` для потоковых моделей: красная точка на крыше |
| `sources` | ссылки на карточку и конфиг |
| `note` | чем модель интересна, одно-два предложения |

`part: "encoder"` или `"decoder"` — для энкодер-декодеров. `loop: { passes, max }` — рекуррентное ядро.

**Весь текст в данных и интерфейсе пишем на английском.** Числа в тексте: `2.8T`, `104B`, `401M`. Комментарии в коде оставляем на русском. Файл `data/models.ru.json` — старая копия, его не обновляем.

## 3. Дообучение

Дообученная модель физически почти не отличается от основы, поэтому отличие показываем зелёными гранями. Заполняем поле:

```json
"retrain": { "value": "Kimi K3", "id": "kimi-k3", "status": "known",
             "source": "https://huggingface.co/...", "note": "what changed" }
```

`id` указываем, если основа есть в парке. Если карточка говорит об этом не прямо, ставим `status: "estimate"` и `confidence`.

Отмечаем только модель, выросшую из отдельной, уже вышедшей модели. Не отмечаем обычный этап внутри одного выпуска (base → instruct) и дистилляцию в новую меньшую модель.

Если размеры те же, копируй этажи основы, а в заметке пиши, что изменилось.

## 4. Добавить или уточнить закрытую модель

Размер закрытых моделей компании не раскрывают, поэтому это всегда `status: "estimate"`, чаще всего `confidence: "low"`. В `note` пишем диапазон и доводы.

- Без исследования порядок величины оцениваем по соседям: цена, скорость, индекс Artificial Analysis, сравнение с открытыми моделями того же уровня.
- Для нового поколения или целого квартала предложи пользователю глубокое исследование. Образцы промптов лежат в `docs/research-prompt-*.md`, результаты кладём в `docs/research-*.md`.
- Проверяй выводы исследований по первоисточникам: они ошибались и противоречили друг другу. Если два исследования расходятся, берём середину по логарифму, а диапазоны объединяем. Так сделано у Google, образец — заметки в его моделях.
- Ссылки на `docs/` на сайте не показываются: у прикидки нужен и внешний источник.
- Не рисуем то, что известно только из слухов.

## 5. Новый провайдер или новый тип

- **Провайдер:** добавь в `providers` запись `{ name, hf_org, logo, logo_source }`. Аватар организации бери по адресу `https://huggingface.co/api/organizations/<org>/avatar`, сохрани в `assets/logos/<org>.webp`, 200×200, на белом фоне. Квартал появится сам.
- **Новый `kind` или формат** правится в `KINDS` и `FORMATS` в `src/main.js` и в легенде `index.html`.
- **Новое устройство, которого здание пока не умеет показать,** не подгоняй молча под существующие элементы: опиши пользователю вариант и согласуй.

## 6. Обновить дату и проверить

1. Поставь в `as_of` сегодняшнюю дату, если реально проверял обновления. При точечной правке одной модели дату не трогай.
2. Запусти сервер конфигурацией `park` из `.claude/launch.json` и открой http://localhost:8080.
3. Проверь:
   - в консоли нет ошибок, счётчик моделей внизу вырос как надо;
   - новое здание стоит в своём квартале, размер выглядит правдоподобно рядом с соседями;
   - карточка: числа совпадают с источником, текст на английском;
   - «Show it working» запускается у языковых моделей.

Если панель браузера скрыта, страница не рисует кадры и скриншот будет пустым. Тогда открой `?shoot&model=<id>` или `?shoot&quarter=<Провайдер>` и запиши клип кнопкой ●: кадр можно извлечь через ffmpeg из `shots/`.

## 7. Опубликовать

Публикуем только по просьбе пользователя: это меняет живой сайт.

1. Запусти `python tools/build_dist.py`: появится `dist/llm-nagiyev-com.zip`.
   Сайт — PWA: `sw.js` отдаёт свои файлы сначала из сети, поэтому обычное обновление данных ничего не требует. Если меняется список файлов сайта, добавь их в `FILES` в `tools/build_dist.py` и в `SHELL` в `sw.js`, а в `sw.js` подними версию `CACHE`. Иконки пересоздаёт `python tools/make_icons.py`.
2. Обнови раздел «Текущее состояние» в `README.md`.
3. Загрузи и распакуй архив одним SSH-соединением. Общий хостинг обрывает частые повторные подключения, поэтому всё делаем за один вызов, а после обрыва ждём 20–30 секунд. Готовая команда с адресом хостинга лежит в `deploy.local.md` рядом с этим файлом: он только локальный, в публичный репозиторий не попадает. Если файла нет, спроси у пользователя доступ. Схема команды: `ssh ... 'cat > ~/tmp/llm.zip && cd <папка сайта> && unzip -o -q ~/tmp/llm.zip && rm ~/tmp/llm.zip' < dist/llm-nagiyev-com.zip`.

   `unzip -o` заменяет файлы, но не удаляет лишние: если файл убран из сайта, удали его на сервере отдельно. Работает только вход по ключу; пароли не запрашивай и не вводи.
4. Проверь живой сайт: файлы отвечают 200, `data/models.json` совпадает с `dist/site/data/models.json`, страница открывается без ошибок в консоли.
5. Коммит — только если пользователь попросит.

В конце коротко скажи: что добавлено, что осталось прикидкой, что не проверено. Напомни, что уже снятые клипы для роликов показывают старый город: новый клип будет от них отличаться.
